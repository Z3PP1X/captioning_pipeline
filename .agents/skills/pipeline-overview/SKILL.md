# Captioning pipeline - overview

Builds LoRA training datasets from long videos: a human splits each video into scene **chunks**, the pipeline samples and scores candidate frames, the human curates the best 300, a VLM captions them, and they are exported as PNG + caption pairs. A second tool (RAG prompt director) mines the finished captions to generate Krea image prompts.

Backend: Python 3.12, FastAPI, SQLite, PyAV/OpenCV, ONNX (CLIP), OpenRouter VLMs. Frontend: Angular 22 + Tailwind v4 + Spartan in `src/web` (legacy `src/web/app.js` remains in the tree).

## Environment rules (AGENTS.md - mandatory)

- Everything runs in **WSL 2 Ubuntu**; never run python/uv/node natively on Windows. Use `scripts/`:
  - `bash scripts/setup.sh` (uv sync) - `bash scripts/run.sh` (uvicorn :8000 `--reload`, API + whatever frontend is already built) - `bash scripts/test.sh [pytest args]`.
- Venv `~/.venvs/captioning_pipeline`, caches/SQLite/previews/filmstrips/RAG index in `~/.cache/captioning_pipeline` (ext4). Only source and `data/finished` live on `/mnt/c`.
- `scripts/env.sh` hard-codes `/mnt/c/Users/Patri/...`; on other machines override `PROJECT_ROOT`, `CP_VIDEO_DIR`, `CP_FINISHED_DIR`.
- Config: `Settings` (env prefix `CP_`: `VIDEO_DIR, CACHE_DIR, FINISHED_DIR, MIN_DURATION_S`; derived: `project_root` = `finished_dir/../..`, `curated_dir` = `<project_root>/data/curated_2500`, `openrouter_api_key` from env `OPENROUTER_API_KEY`) + UI-editable `DEFAULT_USER_SETTINGS` in the `settings` table.

## Web build / run flow

- `package.json` / `angular.json` at repo root; Angular `sourceRoot` = `src/web`, build output `src/web/dist` (gitignored, along with `node_modules/`, `.angular/`). `proxy.conf.json` proxies `/api` + `/static` to :8000.
- `scripts/build_web.sh`: `ng build --configuration development` using `./node_modules/.bin/ng`, sets `NG_CLI_ANALYTICS=false`, writes `~/.angular-config.json`, and `NODE_OPTIONS=--require scripts/patch_os.js` (stubs `os.networkInterfaces()` with dummy interfaces so Node/Angular don't crash on WSL network enumeration).
- `scripts/start_web.sh`: `ng serve` on :4200 with the proxy. `scripts/start_all.sh`: build the frontend, then source `env.sh` and start uvicorn on :8000 (no `--reload`).
- `api.py` serving: static dir = `src/web/dist/browser` (or `src/web/dist`) if it has `index.html`, else `src/web`; mounted at `/static`, plus catch-all `GET /{path}` returning the file or `index.html` (SPA fallback). Angular must therefore be built before FastAPI serves it; unknown `/api/...` GETs return HTML, not 404.
- Note: scripts run `npm`-less (`node_modules/.bin/ng`); `npm install` must be done in WSL.

## Pipeline stages and video status

| Stage | Trigger | Result / status |
| --- | --- | --- |
| Index | startup + `POST /api/videos/scan` | `videos` rows, `new`; `broken=1` flagged |
| Reconcile | startup + scan + `POST /api/videos/sync-captions` (`reconcile.py`) | caption `.txt` files in `finished/per_video/*/` matched to frames (`{slug}_c{NN}_{pts_ms}.txt`, +-50 ms) -> `exports` rows; stuck statuses healed |
| Filmstrip + cuts | `GET .../filmstrip` | webp thumbs + frame-accurate `cuts[]` + fade `transitions[]` (`cuts.py`, setting `cut_detector`) |
| Chunking (human) | `PUT /chunks`, `POST /chunks/suggest` | `chunks`, status `chunked` |
| Extract + score 750 | `POST .../extract-750` -> job `extract_750` | `extracting_750` -> `curating_300`; `frames` + `picks` |
| Curate 300 (human) | picks PATCH / swap-frame / keep_all / reject_all | pick `state`/`role` |
| Caption | `POST .../caption-openrouter` -> job `openrouter_caption` | `captioning` -> `exported`; per-chunk `caption_model` used as layer-1 model when `use_chunk_models`. Each caption is a `captions` row (see Captioning v2 below) |
| Export | `POST /api/export` | PNG (multiples of 16) + caption txt, `exported` |
| Auto-process | `/auto-process`, `scripts/batch_auto_process.py` | job `auto_process`, ends `exported` |

Status handling: startup no longer blindly resets `extracting*` to `chunked`; orphaned running/queued jobs are marked `error`, then `reconcile_captions_and_state` recomputes each video that has no active job: `exported` if exports >= picks > 0; `curating_300` if picks exist; `chunked` if frames or chunks exist; `new` if it was in a transitional state with nothing; `skipped/ignored/broken` untouched. Failed extract/caption jobs reset `extracting_750`/`captioning` to `curating_300` (has picks) or `chunked`. Other statuses present: `chunking`, `extracting`, `curating` (legacy per-chunk/auto-process).

## Domain vocabulary

- **Chunk/scene**: time range with `budget_pct` (sums to 100, max 15 per video), `k` (>=5), `rule`, `tags`, `notes`, `caption_model` (new column, default `google/gemma-4-31b-it`; added by safe `ALTER TABLE` migration in `db.py`). `get_video_scenes_caption_stats` adds `picks_count/exports_count/captioned_count/total_frames/is_fully_captioned/caption_progress_pct`.
- **Candidate pool** ~750 frames scored on 7 dimensions (`scoring.py`: tier-1 metrics + CLIP zero-shot `zs_scores`); **pick** = curated 300 with per-chunk quota `round(300*budget/100)`; **runner_up** ~450. Pick `state`: `keep|reject|star|candidate`. Distribution quotas: multiple ~50%, one person 25-30%, tools/equipment 20-25%, face>=50% prioritised.
- **Caption cascade**: layer 1 (Gemma, or the chunk's model) -> DeepSeek -> Grok only for refused frames; frames <=512 px; modes `concept|character|style`.
- **RAG prompt director** (`pipeline/rag`): `RagCaptionIndexer` reads the `captions` table (`vlm` + `imported`, never `stub`; images via `exports`/`frames`), falling back to `*.txt` files in `curated_dir` (`data/curated_2500/{train,val}`) and then `finished/merged`; table and merged captions get a deterministic 10% `val` split (sha1 of the frame id / stem). It segments them into taxonomy categories (`equipment, surroundings, position, camera_lighting`), embeds them (`rag_index.sqlite` + `rag_embeddings.npz` in the cache dir; build with `python scripts/index_rag.py [--limit --batch-size --incremental]`). R1: besides one CLIP text vector per whole caption (CLIP truncates at 77 tokens, about 55 words), every domain segment is embedded in chunks of at most 40 words (`seg_ids/seg_domains/seg_embeddings` in the same NPZ); `dense_mode` `domain` (default) scores each query domain against the caption's chunks of that domain, `whole` the old way; indexes without domain vectors fall back to `whole` and the next incremental update backfills them. R3: the captions' images (`rag_captions.img_rel_path`) are embedded with SigLIP (`Xenova/siglip-base-patch16-224` quantized ONNX vision tower via `huggingface_hub`, `rag/image_embedder.py`), else offline the CLIP vision model, into `rag_image_embeddings.npz` during full and incremental builds (setting `rag_image_index`, default true; `CP_RAG_IMAGE_EMBEDDER=clip|off`); `GET /api/rag/similar?frame_id=` is "more like this frame". R6: after each successful caption job `auto_reindex.py` (registered by `api.py` for its JobManager; setting `rag_auto_reindex`, default true) queues `RagIndexJob.request_incremental`, which embeds only new/changed captions and hot-reloads the retriever. R10: `evaluation.py` / `scripts/eval_rag.py` / `GET /api/rag/eval` report sibling recall@k/MRR and tag recall/precision@k on the val split, to compare retrieval changes; `RagRetriever.retrieve` = RRF of tag-match score, dense similarity (whole or per-domain) and BM25; `RagRetriever.similar` = image-embedding nearest neighbours; `RagPromptGenerator.generate` (OpenRouter or local Ollama URL) produces three archetypes A (tags), B (short anchor), C (dense narrative) with the trigger at token 0, adult-only constraint, character presets (`sara`, `lene`); `linter.lint_prompt` strips weights/sludge/preambles and checks token budgets. `taxonomy.py` holds `TAXONOMY_CATEGORIES`, `CURATED_PRESETS`, `CHARACTERS`. Endpoints under `/api/rag/*` (see `api-contract`).

## LoRA profile (decision 1)

`videos.profile` `concept|character` (`pipeline/profiles.py`, toggle in the workflow bar). `character` = identity gate on the target person (off-target picks swapped for matching runners, solo first), 2:3 portrait crops for multi-person picks, and `character` caption mode by default. Applied after extraction, after face re-evaluation and via `POST /api/videos/{id}/apply-profile`.

## Image tagging (learn-as-you-tag)

`pipeline/image_tags.py` (`ImageTagEngine`, owned by `JobManager.image_tags`) + routes in `pipeline/tag_routes.py` (mounted from `api.py`). Like persons for faces, tags are **global**: what is learned on one video is suggested on all others.
- **Teach:** in the Curate lightbox press `T` (or "Mark region"), drag a box, name it. The crop (plus its mirror) is CLIP-embedded and stored as a positive exemplar in `tag_regions` (`polarity`, `source manual|accepted|rejected|context`). The non-overlapping windows of the same frame are stored as hidden `context` negatives linked by `parent_id` (cascade): without them one exemplar also matches its own background.
- **Suggest:** each frame is embedded as 19 multi-scale windows (full, 3x3 half-size, 3x3 thirds), cached per video in `<cache>/tag_windows/<video>.npz` (fp16). Per-tag score = noisy-OR of the exemplar term (top-3 cosine vs a calibrated threshold) and a fading CLIP text prior (`prompt`, default "a photo of <name>"), suppressed where a window is closer to a negative. Best window (refined by score-weighted union) = suggested box. Suggestions >= `tag_suggest_min_score` (0.5) go to `frame_tags` (`suggested`); user decisions are `confirmed`/`rejected` and never overwritten.
- **Learn:** accept = positive exemplar at the (adjusted) box; reject = negative exemplar + frame `rejected`; un-tag deletes that frame's exemplars. Every change recalibrates the tag (`threshold`, leave-one-out `accuracy`, shrunk to the default while few exemplars) and re-scores the cached frames of the video at once (SSE `tags_updated`); the first teach on a video queues a `tag_suggest` job for the unembedded frames. After `extract_750`, `auto_suggest_tags` (default on) queues it too.
- **Downstream:** curation frames carry `tags[]` (grid chips, tag filter); confirmed tag names lead stub captions and the export sidecar (`image_tags`), and are passed to the VLM as "verified visible elements" hints.
- Tables `image_tags, tag_regions, frame_tags`; exemplars outlive frames (`frame_id ON DELETE SET NULL`), crops in `<cache>/tag_regions/`.

## Module map (`src/pipeline`)

**Captioning v2 (Phase G).** Prompts are versioned files in `src/pipeline/prompts/` (`concept.md`, `character.md`, `style.md` = system prompt, `=== USER ===`, mode-specific user message; shared `glossary.md`); nothing is read from `~/.gemini` or `/mnt/c` at runtime. `prompt_version(mode)` = `<mode>-<PROMPT_VERSION>-<sha8 of the files>` is stored per caption: bump `PROMPT_VERSION` in `prompts/__init__.py` when the intent changes (any edit changes the hash). `TRIGGER_PROFILES` hold per-mode word ranges, the expected lead (`<trigger> Photograph of` / character: `<trigger> Photograph of a <class noun>`) and discouraged terms (identity traits for character, style words for style). Trigger stays at token 0 and the video title hash at token 1 in every mode. Default temperature 0.4. `openrouter.validate_caption_gate` rejects captions outside the hard word limits (half the minimum, 1.5x the maximum), with preambles (`Here is`, `This image shows`), refusal residue (`I can't`), no closing sentence, a missing trigger or minor-coded words (adults only; bare `girl` is rewritten to `adult woman`); `ModelRefusalError`, `CaptionTruncatedError` and `CaptionValidationError` (`CASCADE_ERRORS`) move a frame L1 -> L2 -> L3, then it is a per-frame failure. The `captions` table (`captions.py`; `frame_id` PK, text, model, layer, mode, prompt_version, trigger, word_count, cost_usd, tokens, warnings, job_id, source `vlm|imported|stub`) is the source of truth: the caption job writes `vlm` rows with OpenRouter usage/cost (`usage: {include: true}`), reconcile and the exporter adopt legacy `.txt` captions as `imported` (idempotent) and stubs as `stub`, and the exporter rewrites `.txt` files from accepted rows. `GET /api/captions/stats`, `GET /api/frames/{id}/caption`.

**Extraction / selection v2 (Phase F, CPU only).** Sampling keeps the sharpest/stillest of 3 sub-samples per sampling window (`decode.sample_chunk_frames(window_peak=...)`, setting `window_peak_sampling`) and drops consecutive near-identical samples by dHash (`metrics.dhash_dedup_consecutive`, `dhash_dedup_max_distance`) before metrics, faces and CLIP; `job_finished.stats.dhash_dropped` reports it. Every curation action is logged to `curation_events` with a feature snapshot; `learned_weights.py` fits per-component weights by logistic regression (`POST /api/scoring/learned-weights/fit`, >= 50 events) that `ScoringEngine` blends in only with `use_learned_weights`. `POST /api/videos/{id}/reselect` (`reselect.py`) re-runs pick vs runner_up from stored embeddings and scores (quality-weighted facility location, per-chunk floor/cap, starred/exported frames locked) without decoding.

**Phase F2 (CPU only, no new pip deps; details in `api-contract`).** `analysis.py`: per-video analysis cache `<cache>/analysis/<video>.npz` (decoded 512 px samples as JPEG + signals, sampling coverage, CLIP/DINOv2 embeddings per crop) and the `frame_features` table (per sampled timestamp: signals, dHash, face summary, gates, quality components, embedding refs); `JobManager._sample_candidates(analysis=...)` decodes only uncovered ranges, so re-extracting a chunk is mostly cache hits (setting `reuse_analysis_cache`; invalidated when the video's size/mtime changes). `cuts.py`: frame-accurate content cut detector (HSV delta per decoded frame at native rate, AdaptiveDetector rule, fade-through-black handling) behind `cut_detector` ('content' | 'legacy'), used by the filmstrip and therefore autochunk/autopilot. `quality.py`: quality v2 (`quality_v2`): chunk-relative hard gates (dark/blown/clipping/letterbox-black/blur), then per-video percentile-normalised subject sharpness, noise, exposure, face size/pose and motion feeding `zs_scores.sharpness`/`quality` of the unchanged composite (learned weights still blend); optional `iqa_model` (`clip_iqa`, or TOPIQ-NR ONNX from HF, offline -> skipped). `embedders.py`: DINOv2-S ONNX (letterboxed) as optional `selection_embedder` for reselect, CLIP fallback. `reselect.py`: axis caps (`multi_person|solo|equipment|face` max shares) and cross-dataset dedup against frames exported from other videos (`POST /api/videos/{id}/reselect` `axis_caps`, `cross_dataset_dedup`). Tests: `tests/test_phase_f2.py`. Still open: per-frame transition-zone exclusion in sampling, cross-dissolve detection, shot ids in reselect, a route exposing `frame_features`, UI knobs.

`api.py` routes + SPA serving - `db.py` (JSON cols auto-decoded) - `face.py` (YuNet + SFace face recognition) - `jobs.py` JobManager + SSE - `reconcile.py` - `autochunk.py` / `autoprocess.py` - `indexer.py` - `decode.py` (PyAV) - `metrics.py` - `classifier.py` / `tagger.py` - `scoring.py` / `select.py` - `openrouter.py` + `prompts/` (versioned caption prompts) - `captions.py` - `export.py` - `streaming.py` (HTTP 206) - `image_tags.py` / `tag_routes.py` (learn-as-you-tag) - `learned_weights.py` / `reselect.py` (Phase F) - `analysis.py` / `cuts.py` / `quality.py` / `embedders.py` (Phase F2) - `rag/` (`indexer, retriever, generator, linter, taxonomy, history, index_job, auto_reindex, evaluation, image_embedder`). Tables: `videos, chunks, frames, picks, persons, video_persons, image_tags, tag_regions, frame_tags, jobs, exports, captions, curation_events, frame_features, settings` (+ separate `rag_index.sqlite`).

Frontend map (`src/web/app`): `core/{models,services,utils}` (api, chunk, curate, dataset, hotkey, job-event, prompt-rag, settings, video services), `features/{shell,studio,curate,dataset,modals,prompt-clicker}` (+ `shared/ui` Spartan helm). See `angular-migration`, `studio-ui-spec`.

- API changes must be reflected in `api-contract` and the Angular models.
- Never commit `.env`, `*.db`, extracted frames, `data/finished`, `node_modules`, `src/web/dist`.
