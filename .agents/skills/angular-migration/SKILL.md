# Angular frontend - current state

Read with `studio-ui-spec` (behaviour + parity status), `api-contract` (backend shapes), `styling` + `design-system` (rules; compliance gaps listed in `design-system/references/studio-adaptations.md`).

The migration landed in upstream commit `258a2d3` ("RAG-powered Krea Prompt Clicker"). It is a working first pass, **not** a finished migration: see "Gaps".

## Stack and files (verified)

- Angular 22 (`^22.1.8`), TypeScript ~6.0, Tailwind v4 via `@tailwindcss/postcss` (`.postcssrc.json`), `@spartan-ng/brain ^1.6.3` + vendored helm, `@ng-icons/lucide`, `class-variance-authority`, `tailwind-merge`, `@angular/forms/signals` (Signal Forms, `@publicApi 22.0` in the installed 22.2). **Zoneless**: `provideZonelessChangeDetection()`, no `polyfills` entry in `angular.json`, `zone.js` removed from `package.json` (it was only an optional peer of `@angular/core`).
- `angular.json`: one project `captioning-pipeline`, `sourceRoot: src/web`, builder `@angular/build:application`, `browser: src/web/main.ts`, `index: src/web/index.html`, styles `src/web/styles.css`, **`outputPath: src/web/dist`** (so the app ends up in `src/web/dist`). Unit tests configured with `@angular/build:unit-test` runner `vitest` (`npx ng test --watch=false` runs 28 spec files / 189 tests as of 2026-10-16, zoneless TestBed). Production budgets: initial 2 MB warn / 5 MB error, component styles 10/20 kB.
- `tsconfig.json`: strict + `strictTemplates`; path aliases `@spartan-ng/helm/*` -> `src/web/shared/ui/*/src/index.ts` and `@app/*` -> `src/web/app/*` (the app itself mostly uses relative imports).
- `src/web/index.html`: light theme default, `<base href="/">`, `<body class="bg-canvas text-foreground h-screen overflow-hidden"><app-root>`.
- `src/web/styles.css`: Tailwind import + Spartan preset, `@theme` mapping and the **mim26 tokens** (`:root` light), reduced-motion rule, thin scrollbars.
- `src/web/app.js` and `src/web/shared/components/**` have been completely removed.
- `components.json` configured for Spartan UI with Vega style and `@spartan-ng/helm` path aliases.
- Zero `ngModel` / zero `FormsModule` across the entire app (all two-way bindings use direct signals).

## Architecture as built

```
src/web/main.ts                 bootstrapApplication(AppComponent, appConfig)
src/web/app/
  app.config.ts                 provideZonelessChangeDetection, provideHttpClient(withFetch, withInterceptors([apiErrorInterceptor])), provideSpartanHlm
  app.component.ts              shell + tab state + hotkey registration + SSE start + Board / Workflow navigation
  core/models/                  video, chunk, candidate, job, dataset, settings, prompt-rag
  core/services/                api (+ api-error, api-error.interceptor), video, chunk, curate, dataset, settings, job-event,
                                hotkey, prompt-rag, workflow, person, tag, confirm, ui-state, autopilot
  core/utils/settings-validation.ts  NUMERIC_SETTING_RULES + settingsFormSchema (Signal Forms) for the Settings dialog
  core/utils/time.utils.ts      formatTime, formatShortTime, formatHms, parseTimestamp
  core/ui/status.ts             unified videoStatusMeta mapping, videoStatusLabel, derivedVideoStatus (decision 3)
  features/shell/               header, video-queue, toast-container, workflow-bar
  features/pipeline-board/      pipeline-board (all videos by stage, batch rescan/export)
  features/studio/              studio-view, video-status-menu (status badge + overflow menu), video-player (controls + watermark canvas), timeline, chunks-panel
  features/curate/              curate-view, curate-toolbar, distribution-bar, candidate-grid
  features/dataset/             dataset-view
  features/modals/              lightbox (custom), settings / openrouter / person / tag-manager (hlm-dialog)
  features/tags/                frame-tags-panel, region-overlay (lightbox tagging)
  features/prompt-clicker/      Prompt Director / RAG view
```

- **State**: `providedIn: 'root'` services holding `signal()`/`computed()` (`VideoService`, `ChunkService`, `CurateService`, `DatasetService`, `SettingsService`, `JobEventService`, `PromptRagService`, `WorkflowService`). Components are standalone, `OnPush`, inline `template:` strings, `@if/@for/@switch`, `input()/output()` mix with decorators (`@ViewChild` in timeline/studio-view, `@HostListener` in the shell).
- **Workflow State Machine**: `WorkflowService` derives step progression (Chunk -> Extract -> Curate -> Caption -> Done) and computes the single primary `nextAction` with `whyDisabled` context. Displayed in `WorkflowBarComponent` and `PipelineBoardComponent`.
- **Navigation**: `AppComponent.currentTab` signal (`board | studio | curate | dataset | prompt-clicker`), defaulting to `board`.
- **Testing**: Vitest via `@angular/build:unit-test` (jsdom). Specs: `time`, `chunk-fields`, `hash-route`, `prompt-export`, `settings-validation` (incl. schema parity) utils; `api` (HttpTestingController), `chunk`, `curate`, `confirm`, `hotkey`, `person`, `prompt-rag`, `settings` services; `confirm-dialog`, `settings-modal`, `dialogs` (person, tag library, lightbox focus), `toast-container` (sonner mirror, actions, persistence), `video-status-menu` (skip / restore / advanced + confirm) components; `core/ui/status`; `hlm-input`, `hlm-native-select` (late options), `hlm-badge` (info + strong icon tokens). Sonner keeps a module-global store: specs call `toastState.reset()` from `@spartan-ng/brain/sonner` before/after each test. Dropdown menus render into the CDK overlay (query `document`); a sub-trigger has `data-slot="dropdown-menu-sub-trigger"`, not `dropdown-menu-item`. Build-cache gotcha: the unit-test builder can reuse a stale bundle when a spec file is restored to byte-identical content - touch the spec if a result looks impossible. Dialog specs query `document` (CDK overlay container) and loop `detectChanges()` + `whenStable()` + a macrotask, because brain dialogs open/close in `afterNextRender`. jsdom has no layout, so CDK's `InteractivityChecker` sees nothing as focusable: override `isVisible()` in focus-trap tests.

## Conventions (zoneless, HTTP, dialogs, forms)

- **Zoneless change detection.** Only signal writes, template/host event listeners and `markForCheck()` schedule rendering; there is no zone to catch `setTimeout`, `await`, `EventSource`, `ResizeObserver` or `requestAnimationFrame`. Any value a template reads must be a signal/computed/input (or a constant). Audit result (all components + services): every template-visible state is already a signal; the remaining plain fields are template-invisible bookkeeping (video-player drag state / `rafId` / ResizeObserver, region-overlay drag start, `JobEventService.eventSource`, `TagService.currentFrameId`, `PromptRagService.statusTimer`, prompt-clicker `copyTimer`, `AppComponent.initialHashPending`). The SSE handlers, toast timeouts, rAF playhead loop and polling timers all write signals. `video-player` uses `viewChild()` signal queries so its source-loading effect also runs once the `<video>` element exists (the old `ngAfterViewInit` duplicate load is gone). Do not add `NgZone`/`zone.js`-dependent code (`fakeAsync` also needs zone.js - use real timers or `vi.useFakeTimers()`).
- **HTTP.** `ApiService` (Promise API: `get/post/put/patch/delete`, `request(method, path, body?)`) wraps `HttpClient` via `firstValueFrom`, always sends `Content-Type: application/json` and serialises bodies itself with `JSON.stringify` (same wire format as the old `fetch` client; HttpClient would send a bare string unquoted). Errors are mapped centrally by the functional `apiErrorInterceptor` (`core/services/api-error.interceptor.ts`, `toApiError()`): `ApiError(status, detail, message)` where `detail` is FastAPI's `detail` (string or object such as `{message, errors}`), falling back to the status text, then `API request failed with status N`; network failures become `ApiError(0, null, 'Network error: ...')` (before: a raw `TypeError`). `ApiService` re-applies `toApiError` so it also works without the interceptor; `ApiError` lives in `api-error.ts` and is re-exported from `api.service.ts`. Service specs keep mocking `ApiService` wholesale; `api.service.spec.ts` covers the real client with `provideHttpClientTesting()`. SSE stays a plain `EventSource` in `JobEventService`.
- **Dialogs.** Settings, OpenRouter, Person and Tag library use `hlm-dialog` + `*hlmDialogPortal` + `hlm-dialog-content` (`class` overrides width/padding via tailwind-merge, built-in close button with `closeLabel`), `hlmDialogTitle` (wires `aria-labelledby`), `hlm-dialog-header/footer`. Always-mounted dialogs bind `[state]="isOpen() ? 'open' : 'closed'"`; the `@if`-mounted ones (person, tag-manager) use `state="open"`; all map `(closed)` to their existing `close` output, so `app.component.ts` is unchanged. Escape: the CDK overlay dismisses the topmost dialog and `HotkeyService` still fires the `escape` action (the shell closes all registered modals first, so the lightbox underneath stays open); both paths converge on the same signals. `registerModal()` (`UiStateService`) is kept so global shortcuts stay suppressed. CDK dialogs bring focus trap, initial focus (`first-tabbable`) and focus restore. Stacking: overlays are ordered by attach time, so the confirm `hlm-alert-dialog` opened from a dialog sits above it; all overlays sit above the custom lightbox (`z-50`). Toasts are the Spartan sonner (`[data-sonner-toaster]`, `position: fixed`, z-index 999999999, above the CDK container's 1000) so they stay readable and clickable over dialogs (brain dialogs do not set `inert` on the rest of the page). Not verified in a browser: whether a click on a toast counts as an outside click for an open dialog. The scrim is now the helm overlay (`bg-foreground/10` + blur) instead of the old `bg-secondary/80`.
- **Toasts.** `JobEventService` keeps the API (`showToast(title, message, videoId?, isError?, action?, persistent?)`, `dismissToast(id)`, `toasts()` signal, 9 s auto-dismiss unless error/persistent). `ToastContainerComponent` renders `<hlm-toaster>` (bottom-right, `expand`, close button, max 5 visible) and mirrors the signal into the sonner store with an effect: new entries -> `toast.error|success|info` (error / has action / otherwise) with `duration: Infinity` (the service timer decides), entries removed by the service -> `toast.dismiss(id)`, sonner close/swipe/action -> `dismissToast`. A typed `ToastAction` becomes the sonner action button and is emitted via `(actionRequest)`; `AppComponent.onToastAction` selects `action.videoId` and switches to `action.tab` (the container no longer selects the video itself). Error toasts are `important` (`aria-live=assertive`).
- **Selects.** No raw `<select>` left: filters, chunk rule/model, grid chunk model, caption dialog, player speed and queue filter use `hlm-native-select` with `[value]` + `(valueChange)` (string values: wrap numbers as `'' + n`) and plain `<option>` children, each with a `<label for=selectId>` (often `sr-only`). Option-level `[selected]` is gone: the primitive re-applies the bound value when projected options change (see `styling`, project adaptations). Action-style selects ("Set all models") are a `hlmDropdownMenuTrigger` button + `hlm-dropdown-menu`.
- **Video status (decision 3).** `app-video-status-menu` in the Studio header: `hlmBadge` from `videoStatusMeta` + ghost icon button opening a dropdown-menu (Skip video / Restore to <derived> / Advanced: set status… submenu with all statuses). Non-derived jumps go through `ConfirmService` (non-destructive variant). `derivedVideoStatus` mirrors `reconcile.py` using `kept_count`/`export_count`/chunk count.
- **Lightbox** stays a custom `fixed inset-0` media surface: `role="dialog"`/`aria-modal` on the panel, `cdkTrapFocus` with `cdkTrapFocusAutoCapture` (focus starts on the image area via `cdkFocusInitial`, returns to the opener on close), Escape/arrows via `HotkeyService`.
- **Forms.** The Settings dialog uses Signal Forms: `form(signal<SettingsFormModel>, settingsFormSchema)` with `[formField]` on `hlmInput` (numbers, trigger word), `hlm-native-select` and `hlm-checkbox` (CVA interop). The schema is generated from `NUMERIC_SETTING_RULES` (`validate()` for empty/NaN/non-integer + `min()`/`max()` with the range message); `settingFieldMessage()` picks the one message shown, identical to `validateNumericSetting` (spec checks parity). Errors still show immediately and Save stays disabled while invalid; `submit()` guards the PUT; each open calls `settingsForm().reset(settingsToForm(settings))`. Empty number inputs are `null` in the model (Signal Forms' native number handling). Other dialogs still use plain `[value]` + `(input)` signal bindings.
